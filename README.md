# Session Controller

Приложение для Windows, которое помогает не оставлять свои аккаунты на общих
компьютерах (например, в учебной аудитории).

1. Нажал **«Начать сессию»**.
2. Работаешь как обычно: браузер, Telegram, Discord, Steam, VS Code — открываешь,
   закрываешь, входишь в аккаунты, всё сохраняется.
3. Нажал **«Завершить сессию»** или выключил компьютер (если стоит галочка
   «Выходить из аккаунтов при выключении компьютера») — всё вернулось
   к состоянию до начала сессии, твоих входов на компьютере больше нет.

## Что очищается

| Что | Что именно удаляется |
|---|---|
| Браузеры: Chrome, Edge, Яндекс, Opera, Opera GX, Brave, Vivaldi, Firefox | Входы на сайты, сохранённые пароли, история, закладки, расширения |
| Telegram Desktop | Вход и кэш переписки |
| Discord | Вход |
| Steam | Вход, запомненные аккаунты, вход в магазин внутри Steam |
| VS Code | Вход в GitHub / Microsoft, настройки, история |
| Git и GitHub | Настройки Git (имя, почта), SSH-ключи, вход в GitHub CLI и GitHub Desktop |
| Диспетчер учётных данных Windows | Пароли и токены, сохранённые программами за сессию (Git и др.) |

В окне программы можно снять галочку с того, что очищать не нужно.

> Статус: ранняя разработка. Подробный план — в [docs/PLAN.md](docs/PLAN.md).

## ⚠️ Важно знать

- Откатывается **всё**, что сделано в этих программах за сессию, а не только входы
  (например, история и закладки браузера, настройки VS Code). Файлы в «Загрузках»
  и твои проекты на диске не трогаются.
- При начале и завершении сессии выбранные программы закрываются.
  Несохранённое в них пропадёт.
- **Не запускай Session Controller из терминала VS Code**, если в списке стоит
  галочка «VS Code»: чтобы очистить VS Code, программе нужно его закрыть, а вместе
  с ним закрылась бы и она сама. Запускай двойным кликом по `start.bat`.
- Пока сессия идёт, снимок «как было» лежит в `%LOCALAPPDATA%\SessionController\backup`.
- Если что-то пошло не так, пригодится лог: `%LOCALAPPDATA%\SessionController\log.txt`.

## Установка и запуск из исходников (Windows)

Нужен Python 3.12 или новее: <https://www.python.org/downloads/>
(при установке отметь «Add python.exe to PATH»).

Один раз, в папке проекта (PowerShell или cmd):

```bat
py -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
```

1. `py -m venv .venv` создаёт виртуальную среду (папку `.venv`).
2. Вторая команда ставит библиотеки в эту среду. Повторять после изменения
   `requirements*.txt`.

Если PowerShell пишет «Не удалось загрузить модуль ".venv"», значит папки `.venv`
ещё нет — выполни первую команду.

**Запуск:** двойной клик по `start.bat` в папке проекта. Или из терминала:

```bat
.\.venv\Scripts\python -m session_controller
```

**Тесты движка:**

```bat
.\.venv\Scripts\python -m pytest
```

## Структура

```
session_controller/
├── __main__.py     ← точка входа (python -m session_controller)
├── app.py          ← окно, трей, реакция на выключение Windows
├── session.py      ← движок: начать / завершить сессию, журнал, восстановление
├── targets.py      ← что очищаем: браузеры, приложения, где они хранят входы
├── processes.py    ← поиск и закрытие программ
├── snapshot.py     ← снимок папки или файла и откат к нему
├── registry.py     ← значения реестра Windows
├── credentials.py  ← диспетчер учётных данных Windows
├── settings.py     ← настройки
├── paths.py        ← где лежат файлы программы
└── winapi.py       ← функции Windows, которых нет в Qt
tests/              ← тесты (pytest)
docs/PLAN.md        ← план проекта, этапы, архитектура
start.bat           ← запуск двойным кликом
```

Чтобы добавить новую программу, достаточно описать её в `targets.py`:
какие папки и файлы запоминать и как называется её процесс.
