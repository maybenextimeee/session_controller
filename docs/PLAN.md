# Session Controller — план проекта

## Идея

Компьютеры в аудитории общие. Ты садишься, заходишь в Google, GitHub, Яндекс, Steam
и т.д., а уходя должен вручную выйти отовсюду. Забыл — следующий человек сидит
в твоих аккаунтах.

Session Controller решает это так:

1. Нажимаешь **«Начать сессию»**.
2. Работаешь как обычно, в своём обычном браузере: открываешь его и закрываешь
   сколько угодно раз, входы в аккаунты сохраняются.
3. Нажимаешь **«Завершить сессию»** (или просто выключаешь компьютер, если стоит
   галочка) — и на компьютере не остаётся ничего, что появилось за сессию.

В будущем: облачный аккаунт Session Controller, в котором хранятся твои учётки,
и вход во всё одной кнопкой.

---

## Как «выйти из всех аккаунтов»

Универсальной кнопки «выйти отовсюду» в Windows нет. «Ты вошёл в аккаунт» на
практике означает, что на диске лежит **токен** (cookie, файл, запись в
хранилище паролей). Удалили токен — компьютер больше не имеет доступа к аккаунту.

| Где живут токены | Примеры |
|---|---|
| Папка браузера (cookies, сохранённые пароли, localStorage) | Google, GitHub, Яндекс, ВК, Telegram Web, почта |
| Файлы десктоп-приложений в `%APPDATA%` / `%LOCALAPPDATA%` | Steam, Discord, Telegram Desktop |
| Диспетчер учётных данных Windows | Git, VS Code (вход через GitHub), Office |

### Подход: снимок и откат

Отслеживать каждый вход по отдельности ненадёжно: у каждого сайта свой механизм,
а cookies в Chrome зашифрованы. Вместо этого:

- **«Начать сессию»** — закрываем браузеры и делаем **снимок их папок с данными**
  (например, `%LOCALAPPDATA%\Google\Chrome\User Data`). Кэш не копируем: входов
  в нём нет, а весит он много.
- **Во время сессии** пользуешься обычным браузером через обычный ярлык. Всё
  сохраняется как на своём компьютере, пока ты не решишь закончить.
- **«Завершить сессию»** — закрываем браузеры и **возвращаем их папки к снимку**.
  Всё, что появилось за сессию, пропадает сразу для всех сайтов, без отдельного
  кода под Google, GitHub и т.д.

Поддерживаются Chrome, Edge, Яндекс Браузер, Opera, Opera GX, Brave, Vivaldi, Firefox.
Если какой-то браузер впервые запустили во время сессии, его папка при
завершении просто удаляется целиком.

Что важно знать:

- Откатывается **всё**, что сделано в браузере за сессию: входы, сохранённые
  пароли, история, закладки, настройки, расширения. Компьютер возвращается
  к состоянию «как было до тебя».
- Скачанные файлы (папка «Загрузки») **не трогаются**.
- На стороне сервиса (например, в списке устройств Google) сессия может ещё
  какое-то время числиться, но токена на компьютере уже нет — следующий человек
  ей не воспользуется.

### Приложения и Windows

Та же схема «снимок → откат» работает и для десктоп-приложений — запоминаем
только те папки и файлы, где хранится вход:

| Программа | Что запоминаем |
|---|---|
| Telegram Desktop | `%APPDATA%\Telegram Desktop\tdata` (кэш `user_data` не копируем) и версия из Microsoft Store |
| Discord | `%APPDATA%\discord` (+ PTB и Canary) |
| Steam | `config\loginusers.vdf`, `config\config.vdf`, `%LOCALAPPDATA%\Steam` (токены и встроенный браузер), значения реестра `AutoLoginUser` и `RememberPassword` |
| VS Code | `%APPDATA%\Code` и `~\.vscode-shared` (с версии 1.118 входы в аккаунты GitHub / Microsoft хранятся там, в зашифрованном виде) |
| Git и GitHub | `~\.gitconfig`, `~\.git-credentials`, `~\.ssh`, `%APPDATA%\GitHub CLI`, `%APPDATA%\GitHub Desktop` |
| Happ | `%APPDATA%\Happ` (программа ставится прямо туда вместе с данными) |
| v2RayTun | `%APPDATA%\v2RayTun.net`, текущее подключение `C:\Temp\v2RayTun\connection.json` и `tunnel.json` |
| Hiddify | `%APPDATA%\Hiddify` |
| Clash Verge | `%APPDATA%` и `%LOCALAPPDATA%\io.github.clash-verge-rev.clash-verge-rev` |
| Claude for Desktop | данные приложения из Microsoft Store `%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Roaming\Claude` (и `%APPDATA%\Claude` у старой версии) |
| Claude Code | `~\.claude`, `~\.claude.json` |
| ChatGPT | `%LOCALAPPDATA%\Packages\OpenAI.ChatGPT-Desktop_*` (`LocalCache`, `LocalState`) |
| Codex | `~\.codex` (и приложение, и консольная версия), данные пакета `OpenAI.Codex_*`, если он есть |
| Cursor | `%APPDATA%\Cursor` |

У всех VPN-клиентов вместе с их папками откатываются настройки прокси Windows
(`ProxyEnable`, `ProxyServer`, `ProxyOverride`, `AutoConfigURL`): VPN в режиме
«системный прокси», закрытый силой, оставил бы прокси включённым — и пропал бы
интернет. После отката программа сообщает Windows, что настройки изменились.

**Диспетчер учётных данных Windows** — отдельный механизм: при старте
запоминаем список записей, в конце удаляем появившиеся (кроме служебных записей
Windows). Туда пишут Git (Git Credential Manager), GitHub Desktop, GitHub CLI
и многие другие программы.

В окне есть список «Что очищать» — найденные на компьютере программы, любую
можно выключить. Если найдено меньше шести, список добирается ненайденными
(бледными, с пометкой «нет на ПК»). Кнопка «Все поддерживаемые программы»
открывает поверх окна полный список по группам. Программы, которых на компьютере
пока нет (в том числе Steam), тоже под защитой: если их установят и запустят во
время сессии, их данные при завершении удалятся целиком. Новая программа
становится доступной после перезапуска Session Controller.

Если Session Controller запущен изнутри программы, которую нужно закрыть
(например, из терминала VS Code), он откажется начинать сессию и объяснит почему —
иначе он закрыл бы сам себя.

### Когда происходит очистка

1. **Кнопка «Завершить сессию».**
2. **Выключение / перезагрузка / выход из Windows** — если стоит галочка
   «Выходить из аккаунтов при выключении компьютера» (по умолчанию стоит).
   Программа ловит запрос Windows на выключение и через `ShutdownBlockReasonCreate`
   просит подождать («Session Controller выходит из твоих аккаунтов…»).
   Если галочку снять — сессия переживёт выключение и продолжится после включения.
3. **Аварийный случай** (выдернули питание, всё зависло). Пока сессия идёт, на
   диске лежит её журнал. Если при следующем запуске видно, что компьютер
   перезагружался, а галочка стоит, сессия сразу дочищается. Если завершение
   прервалось на середине, его можно просто повторить: снимок удаляется только
   в самом конце.

Чтобы очистка при выключении сработала, программа должна быть запущена (она
сворачивается в трей). Автозапуск вместе с Windows добавим вместе со сборкой `.exe`.

## Стек

| Часть | Технология | Почему |
|---|---|---|
| Язык | **Python 3.12+** | Ты его знаешь, для этой задачи его хватает |
| Интерфейс | **PySide6 (Qt)** | Нормальный вид, иконка в трее, события Windows, бесплатно (LGPL) |
| Процессы | **psutil** | Найти и закрыть программы |
| Windows API | `ctypes`, `winreg` | Выключение ПК, диспетчер учётных данных, реестр |
| Тесты | **pytest** | Движок проверяется без настоящих программ |
| Сборка в `.exe` | **PyInstaller** (позже можно Nuitka) | Python на компьютере не нужен |
| Установщик | **Inno Setup** | Классический установщик для Windows, бесплатный |
| Автосборка и релизы | **GitHub Actions** + **GitHub Releases** | Каждая версия собирается и выкладывается автоматически |
| Сайт (позже) | Статический сайт на **GitHub Pages** | Бесплатно, кнопка «Скачать» ведёт на последний релиз |
| Сервер (позже) | **FastAPI + PostgreSQL** | Тот же Python |

Честно о минусах Python для десктопа: `.exe` весит 50–80 МБ, а собранные через
PyInstaller программы иногда ложно ругает антивирус. Лечится подписью кода
(для open-source есть бесплатный вариант — SignPath Foundation) или сборкой через
Nuitka. Без подписи Windows при первом запуске покажет окно SmartScreen
«Система Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае».

## Архитектура

```
session_controller/
├── __main__.py     ← точка входа (python -m session_controller)
├── app.py          ← окно (главная и настройки), трей, реакция на выключение Windows
├── theme.py        ← светлая и тёмная тема, шрифты, стиль окна
├── widgets.py      ← переключатели, карточки, фон окна
├── dialogs.py      ← окна-вопросы и сообщения в стиле программы
├── icons.py        ← значок программы и значки браузеров / приложений
├── session.py      ← движок: начать / завершить сессию, журнал, восстановление
├── targets.py      ← что очищаем: браузеры, приложения, где они хранят входы
├── processes.py    ← поиск и закрытие программ
├── snapshot.py     ← снимок папки или файла и откат к нему
├── registry.py     ← значения реестра Windows
├── credentials.py  ← диспетчер учётных данных Windows
├── settings.py     ← настройки (settings.json)
├── paths.py        ← где лежат файлы программы
└── winapi.py       ← функции Windows, которых нет в Qt
tests/
└── test_session.py
```

Главное правило: **интерфейс отдельно от движка**. Движок не знает про кнопки,
поэтому его можно тестировать и позже переиспользовать.

Файлы программы лежат в `%LOCALAPPDATA%\SessionController`:
`settings.json` (настройки), `session.json` (журнал идущей сессии),
`backup\` (снимки на время сессии), `log.txt` (лог — пригодится,
если что-то пойдёт не так).

## Облако и пароли — важно про безопасность

Хранить чужие логины и пароли = делать **менеджер паролей**. Это самая сложная и
рискованная часть проекта, поэтому она в конце, и делать её нужно правильно:

- **Сервер никогда не видит пароли.** Шифрование на устройстве пользователя
  (ключ из мастер-пароля через Argon2id → AES-256-GCM). На сервере лежит только
  зашифрованный «мусор». Утечёт база — пароли не утекут.
- **Двухфакторная аутентификация** для аккаунта Session Controller — обязательно.
- **Общий компьютер может быть заражён** (кейлоггер). Единый мастер-пароль
  собирает все яйца в одну корзину, поэтому вход через QR-код с телефона —
  не украшение, а защита.
- **Автовход не везде будет «без рук».** Google, Steam и другие на новом
  устройстве часто просят 2FA или капчу, а Google блокирует вход из
  браузеров под управлением автоматизации (Selenium / Playwright). Реалистичная
  цель — «Session Controller заполнил логин и пароль, ты подтвердил вход на
  телефоне».
- Если в аккаунтах хранятся данные людей из РФ — нужно будет учесть
  требования 152-ФЗ о персональных данных.
- Альтернатива собственному хранилищу — интеграция с Bitwarden (open source,
  проверенная криптография). Обсудим, когда дойдём.

## Открытые вопросы

1. Какая версия Windows в аудитории (10 / 11)?

Решено: «заморозки» на компьютерах в аудитории нет, так что очистка при
выключении и после сбоя нужна. Приложение со временем будет публичным.
