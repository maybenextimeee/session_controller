# Session Controller — план проекта

## Идея

Компьютеры в аудитории общие. Ты садишься, заходишь в Google, GitHub, Яндекс, Steam
и т.д., а уходя должен вручную выйти отовсюду. Забыл — следующий человек сидит
в твоих аккаунтах.

Session Controller решает это так:

1. Нажимаешь **«Начать сессию»**.
2. Работаешь как обычно, входишь куда нужно.
3. Нажимаешь **«Завершить сессию»** (или просто выключаешь компьютер) —
   и на компьютере не остаётся ни одного твоего входа, сделанного за сессию.

В будущем: облачный аккаунт Session Controller, в котором хранятся твои учётки,
и вход во всё одной кнопкой.

---

## Главный технический вопрос: как «выйти из всех аккаунтов»

Универсальной кнопки «выйти отовсюду» в Windows нет. «Ты вошёл в аккаунт» на
практике означает, что на диске лежит **токен** (cookie, файл, запись в
хранилище паролей). Удалили токен — компьютер больше не имеет доступа к аккаунту.

Где живут токены:

| Где | Примеры | Доля случаев |
|---|---|---|
| Профиль браузера (cookies, сохранённые пароли) | Google, GitHub, Яндекс, ВК, Telegram Web, почта | подавляющее большинство |
| Файлы десктоп-приложений в `%APPDATA%` / `%LOCALAPPDATA%` | Steam, Discord, Telegram Desktop | часть |
| Диспетчер учётных данных Windows | Git, VS Code (вход через GitHub), Office | часть |

### Подход: изоляция вместо слежки

Пытаться «отследить каждый вход и потом разлогиниться» — ненадёжно: у каждого
сайта свой механизм, а cookies обычного Chrome зашифрованы (App-Bound Encryption)
и их почти невозможно аккуратно править снаружи, не задев чужие данные.

Надёжнее — **запускать всё в одноразовой «песочнице» и в конце её уничтожать**:

- **Браузер.** Session Controller запускает обычный Chrome / Edge / Яндекс.Браузер /
  Firefox, но с **отдельным временным профилем** (`--user-data-dir=...` для
  Chromium-браузеров, `-profile ... -no-remote` для Firefox). Все входы на любые
  сайты попадают только в этот профиль. В конце сессии браузер закрывается, а
  папка профиля удаляется. Это работает сразу для **всех** сайтов, без отдельного
  кода под Google, GitHub и т.д.
  - Альтернатива — режим инкогнито. Проще, но может быть запрещён политиками
    в аудитории, и в него сложнее встроить автовход в будущем.
- **Десктоп-приложения** — через «плагины». Каждый плагин знает, где конкретное
  приложение хранит авторизацию. При старте сессии — снимок этих файлов,
  при завершении — закрыть приложение и вернуть файлы к снимку.
- **Диспетчер учётных данных Windows** — при старте запомнить список записей,
  при завершении удалить новые.
- **(Опционально) Скачанные файлы** — предложить удалить файлы, которые появились
  в «Загрузках» за время сессии.

Важная оговорка: на стороне сервиса (например, в списке устройств Google) сессия
может ещё какое-то время числиться, но токена на компьютере уже нет, поэтому
следующий человек ею воспользоваться не сможет.

### Когда происходит очистка

1. **Кнопка «Завершить сессию».**
2. **Выключение / перезагрузка / выход из Windows.** Программа ловит сообщение
   Windows `WM_QUERYENDSESSION` и через `ShutdownBlockReasonCreate` просит
   подождать («Session Controller завершает сессию…»). Времени мало (секунды),
   поэтому сначала удаляется самое важное (cookies, файлы с токенами), потом всё
   остальное.
3. **Аварийный случай** (выдернули питание, всё зависло). У программы есть журнал
   сессии на диске. Если при следующем запуске видно, что сессия не была
   завершена, она сразу дочищается. Для этого программу стоит ставить в
   автозапуск.

## Стек

| Часть | Технология | Почему |
|---|---|---|
| Язык | **Python 3.12+** | Ты его знаешь, для этой задачи его хватает |
| Интерфейс | **PySide6 (Qt)** | Нормальный вид, иконка в трее, работа с событиями Windows, бесплатно (LGPL) |
| Windows API | `ctypes` / `pywin32` | Выключение ПК, диспетчер учётных данных |
| Процессы | `psutil` | Найти и закрыть браузер / приложения |
| Сборка в `.exe` | **PyInstaller** (позже можно Nuitka) | Одна папка / один файл, Python на компьютере не нужен |
| Установщик | **Inno Setup** | Классический установщик для Windows, бесплатный |
| Автосборка и релизы | **GitHub Actions** + **GitHub Releases** | Каждая версия автоматически собирается и выкладывается для скачивания |
| Сайт (позже) | Статический сайт на **GitHub Pages** | Бесплатно, кнопка «Скачать» ведёт на последний релиз |
| Сервер (позже) | **FastAPI + PostgreSQL** | Тот же Python |

Честно о минусах Python для десктопа: `.exe` весит 50–80 МБ, а собранные через
PyInstaller программы иногда ложно ругает антивирус. Лечится подписью кода
(для open-source есть бесплатный вариант — SignPath Foundation) или сборкой через
Nuitka. Если когда-нибудь упрёмся — ядро можно переписать на C#, но начинать
с этого смысла нет.

Без подписи Windows при первом запуске покажет окно SmartScreen
«Система Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае».

## Архитектура (как разложен код)

```
session_controller/
├── app.py            ← окно, кнопки, иконка в трее (только интерфейс)
├── session.py        ← движок: начать / завершить сессию, журнал
├── browsers/         ← поиск установленных браузеров и запуск с временным профилем
├── plugins/          ← по модулю на приложение: steam.py, telegram.py, discord.py …
├── windows/          ← всё, что зависит от Windows: выключение ПК, диспетчер учётных данных
└── storage.py        ← где лежат файлы программы (%LOCALAPPDATA%\SessionController)
```

Главное правило: **интерфейс отдельно от движка**. Движок не знает про кнопки,
поэтому его можно тестировать и позже переиспользовать (например, в фоновой службе).

## Этапы

### Этап 0 — фундамент ✅ (сделано в первом коммите)
- Структура проекта, `requirements.txt`, `.gitignore`.
- Окно с кнопками «Начать / Завершить сессию» (пока без реальной очистки).

### Этап 1 — MVP: браузерная сессия
- Найти установленные браузеры (Chrome, Edge, Яндекс, Firefox).
- «Начать сессию» → создать временный профиль и открыть в нём браузер.
- «Завершить сессию» → закрыть этот браузер и удалить профиль.
- Журнал сессии + дочистка при следующем запуске после сбоя.
- Иконка в трее, таймер «сессия идёт 00:42».
- Исследовать: показывать список сайтов, на которых ты вошёл за сессию.

**После этого этапа программой уже можно реально пользоваться.**

### Этап 2 — автоматическая очистка при выключении
- Перехват выключения / перезагрузки / выхода из Windows.
- Автозапуск вместе с Windows.
- Проверки: что будет, если выключить ПК посреди сессии.

### Этап 3 — приложения и Windows
- Диспетчер учётных данных Windows.
- Плагины: Steam, Telegram Desktop, Discord, VS Code / PyCharm (список уточним).
- Очистка «Загрузок» (по желанию пользователя).

### Этап 4 — распространение
- Сборка `.exe` через PyInstaller, портативная версия (без установки) + установщик.
- GitHub Actions: собирать и выкладывать релиз при каждом теге `v*`.
- Иконка, версия, «О программе».

### Этап 5 — сайт
- Лендинг: что это, скриншоты, кнопка «Скачать» (ведёт на последний GitHub Release).

### Этап 6 — облачные аккаунты Session Controller
- Регистрация / вход, сервер на FastAPI.
- Хранилище учёток (vault) — см. раздел о безопасности ниже.
- Вход на чужом компьютере по QR-коду с телефона (как Telegram Web), чтобы
  не вводить мастер-пароль на общем ПК.

### Этап 7 — автовход
- Кнопка «Войти во всё»: браузер открывает нужные сайты и подставляет логины/пароли.

## Облако и пароли — важно про безопасность

Хранить чужие логины и пароли = делать **менеджер паролей**. Это самая сложная и
рискованная часть проекта, поэтому она в конце, и делать её нужно правильно:

- **Сервер никогда не видит пароли.** Шифрование на устройстве пользователя
  (ключ из мастер-пароля через Argon2id → AES-256-GCM). На сервере лежит только
  зашифрованный «мусор». Утечёт база — пароли не утекут.
- **Двухфакторная аутентификация** для аккаунта Session Controller — обязательно.
- **Общий компьютер может быть заражён** (кейлоггер). Это риск любого способа
  входа, но единый мастер-пароль собирает все яйца в одну корзину. Поэтому идея
  входа через QR-код с телефона — не украшение, а защита.
- **Автовход не везде будет «без рук».** Google, Steam и другие на новом
  устройстве часто просят 2FA или капчу, а Google вообще блокирует вход из
  браузеров под управлением автоматизации (Selenium / Playwright). Реалистичная
  цель — «Session Controller заполнил логин и пароль, ты подтвердил вход на
  телефоне».
- Если в аккаунтах хранятся данные людей из РФ — на этапе 6 нужно будет
  учесть требования 152-ФЗ о персональных данных.
- Альтернатива собственному хранилищу — интеграция с Bitwarden (open source,
  проверенная криптография). Обсудим, когда дойдём.

## Открытые вопросы

Ответы на них влияют на архитектуру — см. обсуждение.

1. Есть ли на компьютерах в аудитории права администратора? Можно ли запускать
   скачанные `.exe` / ставить программы?
2. Учётная запись Windows в аудитории своя у каждого студента или одна общая
   на всех? Сбрасываются ли компьютеры после перезагрузки («заморозка»)?
3. Какие браузеры там стоят? Ок ли, что в сессии нужно работать в браузере,
   который открыл Session Controller, а не через обычный ярлык?
4. Какие десктоп-приложения, кроме браузера, важнее всего?
5. Какая версия Windows (10 / 11)?
6. Для кого приложение: для себя и группы или публично для всех?
