# Session Controller — контекст для Claude

Этот файл Claude Code читает сам в начале каждого чата в этой папке. Держи его
актуальным: закончили этап или приняли решение — обнови «Статус» и «Решения».
Подробности — в [docs/PLAN.md](docs/PLAN.md) (план и этапы),
[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) (запуск из исходников, тесты, сборка,
релиз, структура) и [README.md](README.md) (для пользователей).

## Идея

Компьютеры в аудитории общие: за день там входят в Google, GitHub, Яндекс, Steam,
Telegram и т.д., а уходя надо вручную выходить отовсюду. Session Controller —
программа для Windows:

1. «Начать сессию» → работаешь как обычно, входы сохраняются.
2. «Завершить сессию» или просто выключить ПК → на компьютере не остаётся ничего,
   что появилось за сессию.

Будущее: сайт с кнопкой «Скачать». Приложение будет публичным.

Облачный аккаунт с хранилищем паролей и автовход **закрыты (2026-10-12):** полный
автоматический вход без участия человека на чужих компах не сделать (Google
блокирует автоматизацию, везде 2FA и капча), а менеджер паролей без этого
дублирует Bitwarden и не нужен. Больше к этой теме не возвращаемся.

## Принятые решения

- **Подход — «снимок и откат»**, а не отслеживание каждого входа. При старте
  закрываем выбранные программы и копируем папки/файлы, где они хранят входы
  (кэш не копируем). При завершении закрываем и возвращаем копию на место; что
  появилось за сессию (в т.ч. программы, запущенные впервые) — удаляем.
  Откатывается всё: входы, пароли, история, закладки, настройки. «Загрузки» и
  проекты на диске не трогаем.
- **Диспетчер учётных данных Windows**: запоминаем список записей, в конце
  удаляем новые (кроме служебных Windows).
- **Выключение ПК**: ловим `WM_QUERYENDSESSION` (Qt `commitDataRequest`), через
  `ShutdownBlockReasonCreate` просим Windows подождать и чистим. Галочка
  «Выходить из аккаунтов при выключении» (по умолчанию вкл). Сбой питания →
  журнал `session.json` на диске, при следующем запуске видим другую загрузку
  (`psutil.boot_time()`) и дочищаем. Прерванное завершение можно повторить:
  снимок удаляется только в самом конце.
- **Стек**: Python 3.12+, PySide6 (Qt), psutil, ctypes/winreg, pytest,
  PyInstaller (режим «папка»), Inno Setup (установка для текущего пользователя,
  без админа), GitHub Actions + Releases. Позже: сайт-лендинг на GitHub Pages.
- **Только 64 бит.** 32-битную Windows не поддерживаем: PySide6 (Qt 6) под неё
  не выпускается, а Windows 11 бывает только 64-битной. Установщик сам
  отказывается ставиться на 32 бит (`ArchitecturesAllowed=x64compatible`);
  ARM-ноутбуки с Windows 11 запускают нас через эмуляцию x64.
- **Аудитория**: у каждого студента своя учётка Windows, «заморозки» нет,
  запускать `.exe` можно, пароль админа известен. Важные программы: Telegram,
  Steam, Discord, VS Code, GitHub. **В аудитории Windows 10**, дома — Windows 11:
  всё проверяем на обеих (Windows 10, например, сама не перерисовывает заголовок
  окна после смены темы).
- **Список программ в окне**: в сетке «Что очищать» — найденные на компьютере
  (если их меньше 6, сетка добирается ненайденными — бледными, «нет на ПК», не
  кликаются). Кнопка «Все поддерживаемые программы» открывает панель поверх окна
  (`Overlay` в `widgets.py`) со всеми целями по группам. Ненайденные программы всё
  равно входят в сессию: установят посреди сессии — при завершении их данные
  удалятся. Список строится при запуске программы.
- **VPN и ИИ-клиенты** — отдельные группы (`VPN`, `AI` в `targets.py`). У VPN вместе
  с папками откатываются настройки прокси Windows (`SYSTEM_PROXY`), иначе после
  силового закрытия VPN пропал бы интернет. Портативные программы без установки
  (v2rayN, NekoRay) не поддерживаем: их данные лежат рядом с exe, хоть на флешке.

## Как устроен код

- `session_controller/` — пакет. **Интерфейс отдельно от движка**: `session.py`
  (движок: start/end, журнал, восстановление) ничего не знает про Qt; `app.py`
  (окно, трей, выключение Windows) только вызывает его. `session.start/end`
  зовут `progress(done, total, name)` — для прогресса в окне.
- **Фоновые операции**: интерактивные start/end идут в отдельном потоке
  (`_SessionWorker` + `QThread`), окно не подвисает; `run_task(verb, task, on_done)`
  асинхронный, результат — в `on_done(ok)`. **Выключение Windows** (`on_system_shutdown`)
  остаётся синхронным (система ждёт очистку); если в этот момент идёт фоновая
  операция, ждём её (`while self._busy: processEvents`), чтобы не чистить дважды.
- `targets.py` — что очищаем. Новая программа = новый `Target` (папки `paths`,
  `process_names`, `skip` для кэша, `registry_values`, `exe_paths` для значка).
  Больше ничего менять не нужно. **Одна программа — одна карточка**: разные
  программы не объединять, даже от одного вендора и с общей папкой (ChatGPT ≠
  Codex, Claude ≠ Claude Code). Если у двух программ один процесс (`claude.exe`),
  различаем по пути к exe: `exe_hint` с вариантами через `|`.
- `snapshot.py` — копия/откат папки или файла (длинные пути, read-only, ретраи;
  удаление через переименование в `.sc-trash-*`). `credentials.py`,
  `registry.py`, `processes.py`, `winapi.py`, `autostart.py` — обёртки над Windows.
- Интерфейс: `theme.py` (светлая/тёмная, «чистый лист»: графит + мята→лайм,
  шрифты Bahnschrift и Segoe UI), `widgets.py`, `dialogs.py` (свои окна-вопросы,
  не `QMessageBox`), `icons.py` (значок программы, значки из exe).
  Главная минималистична: шапка, сетка «Что очищать», кнопка «Все программы» и
  одна кнопка сессии внизу (`SessionButton`) — вся информация о сессии на ней,
  отдельной карточки статуса нет. Анимации — `QPropertyAnimation`/`QVariantAnimation`;
  панель поверх окна (`Overlay`) на время анимации рисует снимок карточки.
  Всё окно — колонка не шире `CONTENT_WIDTH` (576 px) по центру (`CenteredColumn`);
  высоту колонки задаёт только видимая страница (`_switch_page`). Esc закрывает
  панель или выходит из настроек (`on_escape`).
- Файлы программы: `%LOCALAPPDATA%\SessionController` (`settings.json`,
  `session.json`, `backup\`, `log.txt`); для тестов переопределяется
  `SESSION_CONTROLLER_HOME`.
- Флаги запуска: `--minimized` (автозапуск, сразу в трей), `--smoke-test`
  (CI: запуститься и выйти).
- `packaging/` — PyInstaller spec, Inno Setup, `build.ps1`, `make_icon.py`,
  `release-notes.md`. `.github/workflows/build.yml` — тесты на Windows, сборка,
  smoke-тест exe, установка/удаление установщика, релиз по тегу `v*`.

## Правила кода

- Все тексты интерфейса, комментарии, docstring-и и документация — по-русски,
  простым языком (как сейчас в коде). Имена в коде — по-английски.
- Комментарии объясняют «зачем», не «что».
- Движок покрыт тестами на ненастоящих программах во временной папке
  (`tests/test_session.py`); то, что требует настоящей Windows, — в
  `tests/test_windows.py` (на других ОС пропускается).
- Изменил поведение — обнови `docs/PLAN.md` (отметь ✅) и `README.md`.

## Правила документации

- **`README.md` — только для пользователя программы**, а не для разработчика:
  что это и как работает, как скачать, установить, обновить и удалить, что
  очищается, настройки, что важно знать, что делать, если что-то пошло не так.
  Без git, коммитов, сборки, запуска из исходников, тестов и структуры кода.
  Пиши простым языком, на «ты», без внутренних терминов (не «цель», а
  «программа в списке»). Внизу — одна мелкая ссылка на `docs/DEVELOPMENT.md`.
- Всё для разработки — в `docs/DEVELOPMENT.md` (запуск из исходников, тесты,
  сборка, релиз, структура), план и решения — в `docs/PLAN.md` и здесь.
- Текст страницы релиза — `packaging/release-notes.md`, тоже для пользователя.
- В README не обещай того, чего нет в релизе (например, файлов, которые
  в релиз не выкладываются).

## Команды (PowerShell, из папки проекта)

```bat
py -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m session_controller
.\.venv\Scripts\python -m pytest
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
```

Запуск без консоли — `start.bat`. Релиз: поменять `__version__` в
`session_controller/__init__.py`, запушить в `main`, дождаться зелёной сборки,
`git tag vX.Y.Z` + `git push origin vX.Y.Z` (тег обязан совпадать с версией).

## Подводные камни

- Не запускать программу из терминала VS Code при включённой цели «VS Code» —
  она закроет сама себя (движок это ловит и отказывается: `processes.launched_from`).
- Установщик закрывать программу силой нельзя — это выглядит как выключение и
  завершает сессию; поэтому `AppMutex` в `installer.iss`.
- `cmdkey` хранит обычные записи как `LegacyGeneric:target=<имя>`.
- Яндекс Браузер — процесс `browser.exe`, отличаем по `exe_hint="yandex"`.
- VS Code ≥ 1.118 хранит входы в `~\.vscode-shared`, а не только в `%APPDATA%\Code`.
- Claude Desktop из Microsoft Store: его процессы (и всё, что запущено из Claude,
  например терминал Claude Code) видят `%APPDATA%\Claude` как подменённую папку
  пакета `Packages\Claude_*\LocalCache\Roaming\Claude`. Настоящие данные — в пакете.
  «Claude for Desktop» закрывает приложение (exe в пакете `…pzs8sxrjxfjjc` или старой папке
  `AnthropicClaude`), «Claude Code» — отдельный `~\.local\bin\claude.exe` и копию
  внутри приложения (`…\claude-code\…`), откатывает `~\.claude` и `~\.claude.json`.
- Папку установки приложения из Store (`WindowsApps` закрыта) берём из реестра:
  `...\AppModel\Repository\Packages\<пакет>` → `PackageRootFolder`.
- Steam без записи в реестре — берём папку по умолчанию `Program Files (x86)\Steam`,
  иначе Steam, установленный посреди сессии, не очистился бы.
- Значки из шрифта Windows (Segoe MDL2 Assets) пиши в коде как `"\ue713"`, а не
  самим символом — он невидимый, и такой код невозможно читать.
